# 外部设备网络互联与跨机操控规范 (External Device Mesh)

本系统配备物理级双向设备互联底座。所有已连接的局域网 Android 设备（ADB）与远程主机（SSH）均由系统实时维护并落盘在容器内部。

---

## 🌟 核心调度哲学：配置文件第一，已有设备一键直连（Zero Friction）

智能体在执行跨机命令时，必须遵循 **“读配置直连 -> 失败快速自愈 -> 缺失才提示配对”** 的最高准则：
1. **杜绝无脑索要地址**：绝不可一上来就问用户“你的 IP 是什么”、“配对码是什么”。
2. **配置文件第一（Single Source of Truth）**：
   - 只要配置文件里已有该主机或设备的信息，**立即直接按配置发起连接并执行任务**！
3. **智能容错与渐进降级**：
   - 只有在配置中的地址连接失败（如目标手机无线调试动态端口变动），或根本未曾添加过该设备时，才引导用户查看新端口或开启配对弹窗。

## 一、 真实物理配置与状态落盘

| 资产类型 | 物理配置文件 | 存储内容与用途 |
| :--- | :--- | :--- |
| **已连接/已知 Android 清单** | `/root/.dsh/connected_devices.json` | App 实时同步的设备列表（`address` IP:端口、`state` 连接状态、`extra` 备注）。 |
| **SSH 远程主机配置** | `/root/.ssh/config` | 标准 OpenSSH 配置文件，每个节点以 `Host <别名>` 声明目标 IP、端口、用户。 |
| **SSH 伴生密码托管池** | `/root/.ssh/passwords.json` | 权限 `600`，JSON 字典 `{"<Host别名>": "明文密码"}`。App 设置页自动同步写入。 |
| **第三方专属私钥池** | `/root/.ssh/keys/id_<别名>` | 权限 `600`，由 App「外部连接 - SSH 管理」选择文件导入或手动填写的私钥。`/root/.ssh/config` 中以 `IdentityFile` 映射绑定。 |
| **本机 Ed25519 凭据** | `/root/.ssh/id_ed25519` (.pub) | 本机公私钥对，用于公钥免密登录。 |

## 二、 SSH 远程主机连接规范（按配置直连）

### 1. 查找配置并直接连入
当用户提到任何主机名（如“连一下 fnos”、“在 家 里跑下 docker”、“连 7500 查下网络”）：

1. **第一步（查配置）**：
   ```bash
   # 查看当前系统已保存的主机清单
   mesh-ssh list
   ```
2. **第二步（直接连）**：
   - **如果配置里已有该主机**：
     直接调用 `mesh-ssh <别名> "<命令>"` 执行！
     系统会自动判断该主机是“密码托管”还是“公钥免密”，全自动注入密码并带 8 秒超时防挂死保护，**全过程无感直连**：
     ```bash
     mesh-ssh fnos "docker ps"
     mesh-ssh 家 "df -h"
     mesh-ssh 7500 "ipconfig"
     ```
   - **如果配置里没有该别名**：
     才向用户反馈：“在配置中未找到主机 [xxx]，请在 App「外部连接 - SSH 管理」中添加该主机或提供连接地址与密码”。

### 2. 跨机文件互传 (SCP)
直接按配置别名传输，无需手动输密码：
```bash
mesh-scp /root/backup.tar.gz 家:/home/qyh/
mesh-scp fnos:/var/log/syslog /tmp/fnos.log
```

### 3. 私钥认证与专属密钥加载机制
1. **自动挂载认证**：只要 `/root/.ssh/config` 中包含 `IdentityFile` 声明（如 `IdentityFile /root/.ssh/keys/id_<别名>`），执行 `mesh-ssh <别名>` 或原生 `ssh <别名>` 时，OpenSSH 客户端会自动加载该专属私钥握手认证，**智能体无需手动拼接 `-i` 参数**。
2. **私钥凭据读取与定位**：
   - 若需定位某主机的专属私钥：先查阅 `/root/.ssh/config` 对应 `Host` 块下的 `IdentityFile` 字段；
   - 专属私钥默认统一落盘于 `/root/.ssh/keys/id_<别名>`；
   - 若遇到连接或权限报错，确认私钥文件权限是否为 `chmod 600 /root/.ssh/keys/id_<别名>`（外层目录权限为 `chmod 700 /root/.ssh/keys`），避免权限过大（如 644/777）被 OpenSSH 拒绝。

## 三、 Android 设备无线互联规范（按配置直连与自愈）

### 1. 设备状态判断与调度流程图
```text
                       [ 用户下达 ADB 跨机操作指令 ]
                                     │
                    读取 /root/.dsh/connected_devices.json
                             及执行 adb devices
                                     │
           ┌─────────────────────────┴─────────────────────────┐
           ▼                                                   ▼
   【已有设备且 state="device"】                     【配置中有该设备，但未连接/离线】
           │                                                   │
  直接执行 adb -s <address> ...                         执行 adb connect <已记录地址>
   (零等待，直接执行任务)                                         │
                                                    ┌──────────┴──────────┐
                                                    ▼                     ▼
                                               【连接成功】          【连接被拒绝/超时】
                                                    │                     │
                                            继续执行 ADB 指令       端口变动或设备重启
                                                                          │
                                                           ┌──────────────┴──────────────┐
                                                           ▼                             ▼
                                                   【已配对过仅端口变动】          【从未配对过的全新设备】
                                                           │                             │
                                                   提示用户查看目标手机           引导用户打开「使用配对码」
                                                   无线调试当前显示的动态端口       获取 6 位码与临时配对端口
                                                   并执行 adb connect            执行 adb pair -> connect
```

---

### 2. 实操调用三步法

#### 第一步：读配置，在线则直接操作
```bash
# 查看已有设备与在线状态
cat /root/.dsh/connected_devices.json
adb devices -l
```
若目标设备（如 `192.168.2.105:41983`）状态已为 `device`，**立即带 `-s` 执行操作**：
```bash
DEV="192.168.2.105:41983"

# 亮屏/点击/输入
adb -s "$DEV" shell input keyevent 224
adb -s "$DEV" shell input tap 500 1000
adb -s "$DEV" shell input text "hello"

# 截图/推拉文件
adb -s "$DEV" exec-out screencap -p > /tmp/remote_screen.png
adb -s "$DEV" push /tmp/file.txt /sdcard/Download/
```

#### 第二步：配置中有记录但离线，尝试直接重连
如果配置文件里有该设备的记录，但当前未连接：
```bash
# 直接尝试用配置里的地址重连
adb connect 192.168.2.105:41983
```
- 若返回 `connected to ...`：自愈成功，立刻继续执行任务；
- 若返回 `Connection refused`：说明目标手机重启或开关了无线调试，导致系统重新随机分配了高位端口。

#### 第三步：端口失效或全新设备，才触发交互
只有在上述重连失败或未配置过该设备时，才提示用户：
1. **已配对设备（仅端口变了）**：
   提示：“目标设备先前的端口已失效，请看一眼该手机「无线调试」主界面显示的当前端口（如 192.168.2.105:xxxxx），我将直接连接。”
2. **全新设备（未建立信任）**：
   提示：“检测到新设备未配对，请在目标手机打开「无线调试 -> 使用配对码配对设备」，告诉我弹窗里的临时配对端口与 6 位配对码。”
   执行：
   ```bash
   adb pair 192.168.2.105:38472 829103
   adb connect 192.168.2.105:41983
   ```

## 四、 防挂死与命令自愈对照表

| 场景 / 报错输出 | 根本原因 | 标准自愈行动 |
| :--- | :--- | :--- |
| **SSH: 找不到主机** | `/root/.ssh/config` 中未登记该别名 | 使用 `mesh-ssh list` 打印已有列表，若无则引导用户在 App 设置界面添加。 |
| **SSH: 密码主机报错** | 密码变动或未录入托管池 | 引导用户在 App 设置页的「外部连接 - SSH 管理」中点击测试连接更新密码。 |
| **ADB: `device offline`** | 设备正在重连或网络瞬断 | 先执行 `adb disconnect <address>` 再 `adb connect <address>` 重置通道。 |
| **ADB: `Connection refused`** | 动态连接端口已更新 | 配置中的旧端口已失效，向用户索取该手机无线调试界面当前显示的新端口。 |
| **ADB: `unauthorized`** | TLS 配对失效或被用户撤销 | 重新引导执行一次 `adb pair <IP>:<配对端口> <6位码>` 刷新信任。 |
